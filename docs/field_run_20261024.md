## 2. FAST-LIO2 无 PGO 建图及验图

1. Studio 选择 **Bunker**，查验 MID360S/IMU `/livox/lidar` 和 `/livox/imu` 的实测频率、底盘和 base_link 里程计。绑定已经验收的 `calibration_bundle` 和现场真实的 MID360S IP 配置，不启用 GLIM/PGO。
2. 建图使用默认开启的 `CustomMsg` 自体过滤：`/field/aligned/lidar → /field/self_filtered/lidar → agt_mid360_adapter → FAST-LIO2`。复用 AGT `agt_pointcloud_core` 的 Range/Box 规则（配置 `agt_field_test_bringup/config/livox_self_filter.yaml`）；不使用全后方大扇区。原始 bag 仍录未经自体过滤的 `/livox/lidar` 与 IMU。Studio 新增过滤状态，应是 `ACTIVE` 并有累计过滤统计；`BYPASS_TF`、`BYPASS_GUARD`、`BYPASS_TIME_BOUND` 都是**过滤未生效**而非成功。扫描末端保护按 FAST-LIO2 配置中的 `lidar_filter_num` 抽样索引及 `lidar_min_range/max_range` 精确计算，控制扫描结束时刻变化不超过 1ms，同时保证足够有效采样点。`BYPASS_LIO_SAMPLES` 也表示整帧没有屏蔽自体点；新安装的 MID360S 几何仍需用 bag 核对。
3. 在建图页输入名称，选择 `FAST-LIO2 · 无 PGO`，按开始。确认原始 bag 开始录制、LIO 点云可见，然后按已批准的现场方案低速完成建图。关图点击“结束并保存建图”，看后台 Job 是否 **PASS**；若 FAILED/INCOMPLETE 留下原始数据查日志，不把不完整资产用于导航。
4. 地图页选择新导入/已登记的 cloud；**预览选中 PCD**。用 XYZ `min/max` 小包围盒删除确定为后向杆件或残影的点，产生新的 cloud ID。这里是 **map/world 坐标**，不是雷达局部坐标；每次删除前核对 3D 位置，切勿框掉温室梁柱/树干等用于定位的稳定结构。PCD 删除覆盖**全量点云**，屏幕仅显示采样预览。原始 PCD 与 clean 版本分别保留。
5. **务必选中清洗后的 cloud ID** 再点“生成二维地图”。转换使用 `local_ground` 局部地面模型，保留未观测栅格为 Unknown。观察 free/occupied/unknown 的连通性、坡面、边界和地图方向。禁行区在二维地图画多边形并保存，已经画的电子围栏会烘焙到 PGM。不凭空把大片 Unknown 全改为 Free。
6. 保存新的 DRAFT 地图；原始 PCD 与 cleaned PCD 不得在定位和 Nav2 中错配：地图的 `source_pcd_sha256` 必须关联到最终 clean cloud，旧地图的重定位资产不能沿用。先定位验证，现场审核通过后另存/标记 ACCEPTED。

保存工作流会明确显示 `正在保存：PCD→GRID→BBS`，只有后台 Job 返回 `PASS` 且存在 `map_version`，Qt 才显示“地图已经保存”。内置自动执行 `agt_global_relocalization_native build_relocalization_assets`，从**当前 cloud.pcd** 导出 `voxelmaps_coords` 和 `global_map_downsampled.pcd`，按 PCD SHA 校验；清洗后的新 PCD 在重新生成栅格时也会重建对应索引。若 3D-BBS 的 CPU 库/可执行文件未安装，界面将显示“地图已保存，BBS 未就绪”，**绝不宣称重定位就绪**。

**Polar Context 单独说明：** 无 PGO 管线只产生融合 PCD 和 `trajectory.csv`，没有供 `build_relocalization_candidates` 输入的 `poses.txt + patches/`。因此不会生成或伪造 `polar_context.db`；此版本使用 BBS 整图粗匹配 + small_gicp 精配准回退。若要高效候选预筛选，须新增真正的 keyframe patch 导出与 yaw/重力坐标一致性校验，并重新针对重复行列做歧义验收。

## 3. 重定位、路径和防贴边

- 启动“定位”先在静止和缓慢运动中确认全局定位匹配、`map -> odom` 一致、路径位置不前后颠倒。**重定位失败不得直接发送 Nav2 目标。**
- 新版本默认 Smac 规划 **`allow_unknown: false`**，不准规划穿过未知区；已有 V3 设定的全局约 `1.00 m`、局部约 `0.85 m` inflation 会保留。窄道如果因此找不到路线，先检查 free-space 是否确实观测完整、机器人 footprint、地图障碍污染；禁止为了让路线通过直接关闭避障。
- Qt 单击目标和保存多点路线会进行 known-free 检查；正式执行前按 Bunker footprint + 0.10 m 余量再次检查终点。**这不代替 Nav2 对整条路线的动态碰撞检测。**
- 每张新 PGM 有新的 map SHA。正式 `navigation` 启动的 `PHYSICAL_NAVIGATION` 报告必须和这张地图的 SHA、机器人 profile SHA、标定 SHA 严格一致。既有急停和外参证据可复用，但**不能伪造或直接挪用旧地图验收报告**。缺这份现场报告，系统会按设计拒绝自主运动。

## 4. 相机拍照任务预检

当前集成仓库的固定依赖清单并**没有完整锁定** `autolabor_c1_bringup`、`camera_gimbal_interfaces`；这些可能来自机器上已有 ROS overlay，需在现场查：

```bash
source /opt/ros/humble/setup.bash
source ~/agt_field_test_ws/install/setup.bash
ros2 pkg prefix autolabor_c1_bringup
ros2 interface show camera_gimbal_interfaces/action/AcquireView
ros2 action list -t | grep -E '/camera_gimbal/acquire_view|/agt/mission/execute'
```

- 确认视频设备和云台串口是**实际枚举的路径**，不能直接假定 `/dev/video0` 永远正确；C1 云台对应 `AcquireView` action 服务端需在线。新增预检：若 `AcquireView` 类型缺失、Action 未就绪或 GUI 未启用相机，会在**派发拍照任务前拒绝**，而不是车先开出去再发现缺相机。
- Qt“添加航点”启用照片并保存路线，路线绑定 `map_id` 与地图 SHA。运行时 V3 `mission_runtime` 按 `NavigateToPose -> 停稳 -> AcquireView -> 保存图像` 逐点执行；至少先做一次受监督短距离单点拍照，检查真实保存的图像路径、图片质量、相机时间戳和航点位姿，再运行全路线。

## 5. 后向杆件的真实边界与验收日志

**历史项目已有自体回波过滤，不要重复实现。** 核对的现有代码：
- `agt_navigation_v3/cleaning/agt_pointcloud_preprocessor/src/obstacle_cloud_node.cpp`：对 `/agt/livox/points` 执行 TF-aware `base_link` 自体包围盒（默认 enabled）及可选 `rear_filter`（默认 disabled），输出 `/agt/navigation/points_obstacles` 给 Nav2；默认 `self_filter.center_xyz=[0,0,0.20]`、`size_xyz=[1.023,0.778,0.400]`、`padding_m=0.05`，实际数据见 V3 `config/perception.yaml`。
- `agt_navigation_v3/cleaning/agt_terrain_map_generator`：已有 `SelfFilter`、`RearFilter`（地形清理支路）。
- `agt_pointcloud_pipeline`（固定提交 `2def1b76b7526b88972a3bc747b47dd7badcc765`）：已实现可配置的 `BoxFilterPlugin`、`SectorFilterPlugin`、raw/rejected/filtered 可视化与 rosbag 分析，mapping 配置默认 `[range,self_box]`，navigation 默认 `[range,self_box,rear_sector]`；该独立模块不等于当前新工作台已调用它。
- 早期后向动态过滤在 FAST-LIO2 body-cloud → OctoMap/二维导航地图旁路已经使用过，不应误认为主 LIO 原始数据经过了同一过滤。

**现已复用底层算法，默认启用。** 新增 `agt_field_test_bringup/src/livox_self_filter.cpp` 直接调用已锁定的 `agt_pointcloud_core::RangeFilter/BoxFilter`，在适配器之前过滤 `livox_ros_driver2/CustomMsg`，维持 `points` 数组长度、`point_num`、索引顺序和逐点 `offset_time` 不变；命中盒的点只把 Livox `tag` 的类型位标记为无效 (`0x20`)，由锁定版本 FAST-LIO2 原有的 `livox2PCL` 跳过。这样保留 `lidar_filter_num` 的固定抽样索引（而不是删除点后改变抽样序列）。TF 无效或过滤率过大等条件会整帧旁路并报警（并非静默丢帧）。默认盒取历史 mapping Profile 数值，在 `base_link` 坐标下评估；换装 MID360S 后务必检查静态 TF 和几何盒范围。世界坐标 PCD ROI 依然是后处理工具，不是逐帧过滤的替代。旧 Nav2 obstacle self_filter 保留独立工作，暂不修改它的后向扇区默认值。

现场保留 raw bag、修正后的 cloud/PGM、`map_id` 和 SHA、每次目标/action 结果、`/agt/mission/status`、相机图片、`/local_costmap/costmap`、`/plan`、`/agt/odometry/local`、`/wheel/odom`、`/tf` 和 CAN 反馈。巡检中出现“贴边、频繁左右摆动”时，比对 planner 路径是否贴边和控制指令是否过度摆动：两类问题不能混为一谈。
