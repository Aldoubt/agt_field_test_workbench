# 2026-10-27 平面控制转换修正与15度机械安装角

状态：OFFLINE_PASS / FIELD_NOT_RUN。用户明确要求修正平面控制转换，并提供机械安装俯仰15度。本次实现、编译和隔离验证完成；未执行物理运动或宣称13–15cm实测偏差已闭环。

## 修改后的行为

普通导航、距离和拍照FollowPath现在使用 `agt_field_test_bringup/PlanarRegulatedPurePursuitController`。该类复用已安装Nav2 RPP 1.1.20，仅将其路径查询通过私有PlanarControlBuffer转换为平面几何：先取得原始完整TF，反转得到机器人在路径坐标系中的位姿，保留原点位置，用yaw替换roll/pitch后再求逆。这样路径z和车体高度不再进入局部xy，航向控制基于一致的二维目标。

只在控制器内部、目标为costmap基座坐标系的查询上做投影。机器人位姿到全局路径坐标系的转换仍使用原始3D TF；原始Buffer未修改，点云/定位/地图仍使用真实三维变换，没有广播或重定义TF。用于显示的RPP局部路径和carrot属于二维控制投影，不得回用于三维点云处理。

原生RPP继续处理路径裁剪、前视、曲率与近障减速、速度限制、倒车和轮廓碰撞预测。新增路径TF预检查：缺失时间戳对应变换时直接失败，不允许Humble逐点转换失败后使用默认空位姿。实现没有复制或替换RPP的避障算法。

参考实现版本：[Nav2 RPP 1.1.20](https://github.com/ros-navigation/navigation2/blob/1.1.20/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp)。该版本原先先完整三维转换，再把z清零，xy中的高度耦合已经发生；仅改显示z无效。

## 使用

停车结束旧会话后按原模式重新启动，例如本轮BBS距离入口：

```bash
./field_start distance --global-backend bbs
```

必须重新定位，避免沿用按13度外参计算的旧全局校正。等待就绪后先录包，再执行 `./field_distance run 5`；记录首次软件到点、实际停止和物理参考点误差。原有2cm位置容差保留，实车停车效果待验证。
